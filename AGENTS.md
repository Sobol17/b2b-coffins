# Инструкции проекта

Владелец: Sobol17. Общение по-русски.

## Контекст и работа

- Начни с `git status --short --branch`, diff и относящегося к задаче кода.
  Сохраняй чужие изменения, файлы, рабочие деревья и процессы.
- Навигация по коду и разделам ядра: [INDEX.md](INDEX.md). Читай нужный раздел,
  не весь индекс или `tech.md` в начале сессии. Тип ищи по имени через `rg`.
- Перед правкой прочитай вложенные `AGENTS.md` затрагиваемых каталогов.
  Они дополняют эти правила; загружать инструкции остальных слоёв не нужно.
- Контракты и правила кода принадлежат `tech.md`. При расхождении с кодом прав
  контракт. Если его не хватает, останови зависимую реализацию по
  [CONTRACT GAP](tech.md#134-contract-gap), независимую работу можно продолжать.
- Одна задача, один сфокусированный diff в отдельной ветке. Worktree нужен
  при занятом checkout или параллельной работе.
- Перед изменением данных, git и внешних систем соблюдай
  [guardrails](docs/guardrails.md). Локальный запуск и проверки описаны в
  [руководстве](docs/agent-workflow.md); открывай его по необходимости.

## Superpowers

Используй `superpowers:using-superpowers` для выбора skills. Диагностика идёт
через `systematic-debugging`, значимая логика и регрессии через
`test-driven-development`, подтверждение готовности через
`verification-before-completion`. Значимое изменение и мёрдж требуют
`requesting-code-review`. Остальные skills применяются по ситуации.

Настройка владельца важнее шаблонов skills: критерии, шаги и решения ведутся
в чате; слайсы, спецификации и файлы планов создаются только по договорённости.
Старые материалы `docs/superpowers/`, `docs/plans/` и §14 ядра являются архивом.
Не копируй установленные skills в проект; о недоступном skill сообщи явно.

## Сдача

Проверки выбирай по [§10](tech.md#10-стратегия-тестов), перед мёрджем выполни
[гейт §11.1](tech.md#111-ci). Делай небольшие логические коммиты по
[§13.3](tech.md#133-коммиты-и-pr). В итоге укажи изменения, фактически
выполненные проверки, ограничения, ветку и коммиты.
