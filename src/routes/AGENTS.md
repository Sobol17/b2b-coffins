# Маршруты

Контракты: корневой `tech.md` §4, §12, §15, §19–20.

- Роут тонкий: право, Zod-разбор входа, сервис, DTO и HTTP-ответ.
  Бизнес-логики и Drizzle в роуте нет. Данные БД загружай в `+page.server.ts`.
- Проверяй право до чтения формы. Layout guard не заменяет проверку действия
  и доступа к конкретной записи. Фильтр контрагента задаёт `ActorContext`.
- Form actions и `use:enhance` для обычных мутаций. В мутациях `+server.ts`
  используй `requireOwnCall`, не пиши свою CSRF-проверку.
- Фильтры реестра через `listQueryOf` и `filtersOf`; списки через общий пайплайн.
  Доменные ошибки `load` переводятся в HTTP через `orHttpStatus`, текст форм
  через `userMessage`. Не выводи внутреннее имя действия пользователю.
- Страницы собирай из `lib/ui` и существующих `lib/crm`, `lib/portal`.
  Для общих примитивов прочитай также `src/lib/ui/AGENTS.md`.
- Изменение CRM-поверхности отражай в `tests/e2e/crm-surface.ts`.
  Проверяй целевую роль, чужую роль и тело ответа на утечку цен.
- Состояние пользователя не хранится модульным singleton на сервере.
  Переходы внутри приложения через типизированные маршруты.
