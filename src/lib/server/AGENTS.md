# Сервер

Контракты: корневой `tech.md` §4–8, §12, §19–20. Эталон: профиль портала K5.

- Сервис наследует `BaseService`, репозиторий `BaseRepository`. Сервис открывает
  транзакцию, передаёт `tx` репозиторию, возвращает DTO. HTTP-объекты сюда не идут.
- Проверяй каждое действие через действующую policy. Скрытая кнопка не защита.
- Портальный репозиторий получает `counterpartyId` из `ActorContext` и включает
  его в `where`. Идентификатор из запроса не подменяет контекст пользователя.
- Соблюдай видимость заявок и станций §19.3. Для роли без цен не выбирай
  закупочные поля из БД и не добавляй их в DTO. Исключения только по §8.1.
- Событие и его outbox записываются в транзакции действия. Топик и payload
  берутся из §7. Новый обработчик проверяется двойным запуском и фейком ошибки.
- Изменения проходят через существующий аудит, переходы через машину состояний
  с записью истории. Платежи и движения исправляются по контракту компенсации.
- Конфигурация приложения только из `config.ts`. SQL параметризованный.
  Ошибки наружу через общие мапперы, без стека, внутренних действий и ПДн.
- Схема в `db/schema/`, миграции только `pnpm db:generate`. Нехватка контракта
  останавливает зависимую реализацию по корневому CONTRACT GAP.
