## Эталон

Портальные экраны собираются по макетам из `ui/`, соответствие экранов и слайсов в `tech.md` §18.

Твой слайс повторяет структуру эталонной вертикали `src/routes/(portal)/portal/profile` (слайс K5): `+page.server.ts` → Zod-схема из `lib/validation` → сервис → репозиторий → аудит → DTO → компонент из `lib/ui` → тесты. Не изобретай свою раскладку файлов.

## Правила кода (кратко, полный список в `tech.md` §12–13)

- TypeScript strict, `any` запрещён.
- Классы: сервисы наследуют `BaseService`, репозитории `BaseRepository`. Роут тонкий, без бизнес-логики и без Drizzle.
- Домен в `lib/domain/**` чистый: без БД, `fs`, `fetch`, SvelteKit.
- Права проверяются на сервере на каждое действие и каждый переход статуса. Скрытие в UI защитой не считается.
- Row-level фильтр по `counterpartyId` из `ActorContext` в каждом портальном запросе.
- Цены роли без цен не приходят из БД. Вырезает `select` и DTO-маппер, не шаблон.
- Весь вход через Zod на сервере, включая `FormData`, query и содержимое импортируемых XLSX.
- Деньги в целых копейках, поля с суффиксом `_minor`. `real` под деньги запрещён.
- Дублирование третий раз выносится в `lib/server/core` или `lib/utils`.
- Файл не длиннее 250 строк, функция не длиннее 40.
- Миграции только `pnpm db:generate` из схемы. Файлы в `drizzle/` руками не правим.
- UI только на shadcn-svelte: CRM целиком и базовые компоненты портала. Вторую UI-библиотеку не подключаем, свои таблицы и модалки не пишем.
- Брак, переделка, приостановка и рекламация контрагента в системе не учитываются. Не заводи под них таблицы, флаги, статусы, события и формы. Единственный обратный переход — `delivered -> ready` при отказе в доставке.
- Приложение работает как PWA (§17), но только ради установки на домашний экран и приёма push. Офлайн-режима нет: не пиши `fetch`-обработчик в service worker, не используй Cache Storage, не делай `offline.html` и фоновую синхронизацию.
- Сканирования QR в системе нет. Не заводи камеру, библиотеки распознавания и QR на печатных формах. Заявку в цехе открывают из списка или поиском по номеру с бланка.
- Docker, деплой на VPS и CD в объём не входят. Не создавай `Dockerfile`, `compose.yml` и workflow деплоя. Пути к БД и файлам берутся из конфига, а не из констант, чтобы деплой заводился позже отдельной задачей.

## Тесты

Тест выводится из критериев приёмки задачи, а не из реализации. Сначала критерий, потом тест, потом код.

На каждый слайс:

- контрактный тест на стыке (payload джоба против Zod-схемы из `tech.md`, ответ сервера для роли без цен);
- тест идемпотентности на каждый новый джоб: прогон дважды с тем же payload, эффект ровно один;
- путь ошибки через фейк драйвера (ошибка, таймаут, ретрай, `dead`);
- property-based (fast-check) на новую чистую логику в `lib/domain`;
- e2e Playwright: целевая роль плюс чужая роль на 403.

PR без тестов гейт не проходит. Порог покрытия `lib/domain/**` — 90% строк.
