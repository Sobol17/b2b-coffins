# Тесты

Источник требований: корневой `tech.md` §10, §12, §13.5 и DoD слайса.

- Выводи тест из критерия приёмки. Для изменения поведения сначала получи
  ожидаемое падение, затем реализуй и проверь успех. Баг закрепляй регрессией.
- `tests/domain/`: fast-check на инварианты чистой логики.
  `tests/unit/`: контракты, сервисы, репозитории и драйверы.
  `tests/e2e/`: сценарии ролей на собранном приложении.
- Для каждого нового джоба: двойной запуск с одинаковым payload, один эффект;
  ошибка и таймаут фейка, ретрай и `dead`, отсутствие частичной записи.
- Проверяй отсутствие закрытых ценовых полей в теле серверного ответа.
  Допустимые исключения заданы §8.1. Чужая станция даёт 403; невидимые записи
  портала могут давать 404 по контракту своего раздела.
- Общие фикстуры и сид переиспользуются. Unit setup создаёт временную БД
  на файл теста; не импортируй серверный модуль до установки её пути.
- Playwright использует `data/e2e.db`, `data/e2e-files` и порт 4173.
  Не подменяй их рабочей БД и не удаляй открытый SQLite-файл.
  Порядок миграций и ограничения запуска описаны в `docs/agent-workflow.md`.
- Полный прогон и сборку не запускай параллельно. Не ослабляй assertions,
  покрытие и проверки прав ради зелёного результата.
- Правка только инструкций не требует искусственного поведенческого теста.
  Проверь ссылки и команды; полный гейт перед мёрджем остаётся обязательным.
