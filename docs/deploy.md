# Деплой демо-стенда

Стенд работает на одном VPS в двух контейнерах. `app` запускает SvelteKit, воркер очереди и SQLite. `caddy` принимает трафик на 80 и 443, сам выпускает сертификат Let's Encrypt и проксирует запросы в `app:3000`.

База и загруженные файлы лежат в томе `b2b-coffins_app-data`, сертификаты в томе `b2b-coffins_caddy-data`. Пересборка и перезапуск контейнеров их не трогают.

## Что нужно от сервера

- Ubuntu 22.04, 24.04 или 26.04, от 1 vCPU, 1 ГБ RAM и 10 ГБ диска. На 1 ГБ сборка образа идёт медленно, поэтому добавьте swap на 2 ГБ. Стенд развёрнут и проверен на 26.04.1 LTS: Docker и нативные модули встают без правок.
- Открытые порты 22, 80 и 443.
- Домен с A-записью на IP сервера. Если домена нет, возьмите адрес вида `203-0-113-10.sslip.io`: он сразу указывает на `203.0.113.10`, и Let's Encrypt выдаёт на него сертификат.

## Первый запуск

1. Поставьте Docker с плагином compose:

   ```bash
   curl -fsSL https://get.docker.com | sh
   ```

2. Добавьте swap, если на сервере 1 ГБ памяти:

   ```bash
   fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
   echo '/swapfile none swap sw 0 0' >> /etc/fstab
   ```

3. Склонируйте репозиторий:

   ```bash
   git clone git@github.com:Sobol17/b2b-coffins.git /opt/b2b-coffins
   cd /opt/b2b-coffins
   ```

   Если репозиторий приватный, сначала создайте на сервере ключ `ssh-keygen -t ed25519` и добавьте публичную часть в Deploy keys репозитория с доступом только на чтение.

4. Создайте `.env` из примера и заполните `APP_DOMAIN` и `SESSION_SECRET`:

   ```bash
   cp .env.production.example .env
   sed -i "s|^SESSION_SECRET=.*|SESSION_SECRET=$(openssl rand -base64 48)|" .env
   nano .env
   ```

   `ORIGIN`, `DATABASE_PATH`, `FILES_DIR` и `PORT` задаёт `compose.yml`, в `.env` их не пишите.

5. Соберите образ и запустите стенд:

   ```bash
   docker compose up -d --build
   ```

   Контейнер `app` при каждом старте применяет миграции и только потом поднимает сервер. `caddy` ждёт, пока `app` ответит на `/api/health`.

6. Наполните базу демо-данными:

   ```bash
   docker compose run --rm app pnpm seed
   ```

   Для показа добавьте демо-заявки «Ритуал-Сервис» во всех статусах и журнал уведомлений. Письма при этом не уходят даже с настроенным SMTP:

   ```bash
   docker compose run --rm app pnpm seed:demo
   ```

   Сид повторно запускать безопасно. Логины и пароли лежат в `scripts/fixtures/counterparties.json` и `scripts/fixtures/crm-users.json`. Репозиторий их раскрывает, поэтому на стенде с реальными данными сид не запускайте.

7. Проверьте стенд:

   ```bash
   curl https://<домен>/api/health
   ```

   Ответ `"status":"ok"` и `"workerRunning":true` означает, что сервер и очередь работают.

## Обновление

Одной командой с рабочей машины, где в `~/.ssh/config` заведён `Host coffins-vps` с ключом и адресом сервера:

```bash
ssh coffins-vps 'cd /opt/b2b-coffins && git pull && docker compose up -d --build'
```

То же самое из сессии на сервере:

```bash
cd /opt/b2b-coffins
git pull
docker compose up -d --build
```

Во время пересборки старый контейнер продолжает отвечать. Перерыв длится несколько секунд, пока новый контейнер применяет миграции и стартует.

Обновление до ядра v1.55 и новее с более старой версии требует одного запуска после старта контейнера. Команда даёт записям работ, внесённым до v1.55, исполнителями весь состав их дня, и старые дни сохраняют прежние начисления. Повторный запуск ничего не меняет.

```bash
docker compose exec app pnpm admin payroll:backfill-crews
```

Каждое обновление, которое добавляет события уведомлений (с ядра v1.57 это обращения контрагентов), требует ещё одного запуска. Сид на стенде не запускают, поэтому новые правила пушей и их тексты приходят этой командой. Она добавляет только недостающие строки: выключенные правила и тексты, которые руководитель поправил в CRM, остаются как были. Повторный запуск ничего не меняет.

```bash
docker compose exec app pnpm admin notifications:sync
```

Обновление, которое добавляет роли (с ядра v1.61 это шлифовщик и обивщик), требует ещё одного запуска. Без него руководитель не сможет выдать новую роль сотруднику. Повторный запуск ничего не меняет.

```bash
docker compose exec app pnpm admin roles:sync
```

Обновление до ядра v1.62 переносит себестоимость из варианта каталога в складскую позицию. Запустите перенос один раз после старта контейнера, иначе себестоимость, заполненная в карточке варианта, пропадёт из реестра склада и отчётов. Повторный запуск ничего не меняет.

```bash
docker compose exec app pnpm admin stock:cost-backfill
```

Обновление до ядра v2.1 переводит цех на станции. Заявки, принятые до обновления, заданий на станциях не имеют, а «Готов к выдаче» теперь ставит только система. Запустите после старта контейнера сначала `notifications:sync`, чтобы пришли правила и текст пуша о новой заявке на станции, затем досылку. Она отправит столяру недостающие штуки заявок в работе и переведёт покрытые складом заявки в «Готов к выдаче». Повторный запуск ничего не меняет.

```bash
docker compose exec app pnpm admin notifications:sync
docker compose exec app pnpm admin shop:sync
```

## Команды администратора

CLI из `tech.md` §2 работает внутри контейнера:

```bash
docker compose exec app pnpm admin user:create --email ... --name ... --role ... --password ...
docker compose exec app pnpm admin request:transition --request ... --to ... --actor ...
```

Файл для `price:import` сначала скопируйте в контейнер:

```bash
docker compose cp prices.xlsx app:/app/data/prices.xlsx
docker compose exec app pnpm admin price:import --file /app/data/prices.xlsx --price-list ...
```

### Каталог из прайса мастерской

`scripts/fixtures/catalog-angel.json` хранит прайс от 01.06.2026: 78 моделей в 11 разделах, по одному варианту на модель. Строки вида «Славянский / Шестигранный» заведены двумя моделями с одной ценой. Файл лежит в образе, копировать его не нужно:

```bash
docker compose exec app pnpm admin catalog:import --file scripts/fixtures/catalog-angel.json --hide-others
```

`--hide-others` снимает с портала модели, которых нет в файле, например демо-модели сида. Фото моделей лежат в `scripts/fixtures/catalog-angel/` и попадают в `FILES_DIR` тем же запуском: фото получает только модель без фото, поэтому повтор не задваивает галерею и не трогает фото, загруженные в CRM. Заявки на них остаются. Повторный запуск обновляет названия и цены и ничего не дублирует. Себестоимость, которую заполнили в CRM, и модели, скрытые в CRM, импорт не трогает. Материал корпуса у гробов и крестов записан как «Сосна»: поправьте его в карточке варианта, где он другой.

## Резервная копия

SQLite работает в режиме WAL, поэтому файл базы копируется через API `backup`, а не через `cp`:

```bash
docker compose exec app node --input-type=module -e "import Database from 'better-sqlite3'; await new Database(process.env.DATABASE_PATH, { readonly: true }).backup('/app/data/backup.db')"
docker compose exec -T app tar --exclude='app.db*' -czf - -C /app/data . > backup-$(date +%F).tar.gz
docker compose exec app rm /app/data/backup.db
```

Архив содержит `backup.db` и каталог `files`. Для восстановления остановите `app`, положите `backup.db` в том под именем `app.db`, верните `files` и запустите `app`.

## Почта

По умолчанию `MAIL_DRIVER=fake`: письма никуда не уходят, в лог попадает только тема письма. Для реальной отправки задайте в `.env` значения `MAIL_DRIVER=smtp`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS` и `MAIL_FROM`, затем выполните `docker compose up -d`. Без `SMTP_HOST` и `MAIL_FROM` контейнер не стартует.

## Web Push

По умолчанию `PUSH_DRIVER=fake`: пуши никуда не уходят, в лог попадает только тег уведомления. Кнопка «Включить уведомления» при этом сообщает, что уведомления не настроены.

Для реальной отправки нужна пара ключей VAPID. Личного кабинета и регистрации у сервисов доставки нет, пара генерируется на сервере:

```bash
docker compose exec app pnpm exec web-push generate-vapid-keys
```

Запишите в `.env`:

```
PUSH_DRIVER=webpush
VAPID_PUBLIC_KEY=<Public Key>
VAPID_PRIVATE_KEY=<Private Key>
VAPID_SUBJECT=mailto:<адрес владельца>
```

Затем выполните `docker compose up -d`. Без ключей и без настоящего адреса в `VAPID_SUBJECT` контейнер не стартует.

Сохраните пару в менеджере паролей. Подписка устройства привязана к публичному ключу: новая пара отключает уведомления на всех устройствах, и людям придётся включать их заново. Приватный ключ в репозиторий не попадает.

Пуш работает только по HTTPS, его даёт Caddy. На iOS пуш приходит только приложению, установленному на экран Домой, начиная с iOS 16.4.

### Приёмка на устройствах

1. Android, Chrome: откройте стенд, нажмите «Установить приложение», запустите его с домашнего экрана.
2. iPhone, Safari: откройте стенд, нажмите «Поделиться», затем «На экран Домой», запустите приложение с домашнего экрана.
3. Войдите водителем, откройте «Уведомления» и нажмите «Включить уведомления на этом устройстве».
4. Переведите заявку в «Готов к выдаче» под администратором мастерской.
5. Пуш приходит на оба телефона. Нажатие открывает экран «Доставка».
6. Под руководителем откройте «Уведомления», вкладку «Журнал отправок»: строка водителя в статусе «Отправлено».
7. В инструментах разработчика Chrome раздел Cache Storage пуст.

## Что стенд не делает

- CD нет: мёрдж в `main` ничего не разворачивает, обновление запускается вручную.
- Автоматического бэкапа нет.
- Офлайн-режима нет: приложение ставится на домашний экран и принимает пуши, но без сети не работает.
