# Документация

- Контракты и роли живут в корневом `tech.md`; читаются нужные задаче разделы.
  Не создавай вторую дорожную карту или копию схемы БД.
- Корневой `INDEX.md` описывает расположение кода. При переносе модуля обновляй
  его путь в карте; правила и контракты в индекс не дублируй.
- Инструкции агента в `AGENTS.md`, `docs/agent-workflow.md` и `docs/guardrails.md`.
  Вспомогательные файлы читаются по ссылке; не считай их автоматически загруженными.
- Новые планы и спецификации по умолчанию не создаются. Процесс задают
  Superpowers и текущая задача в чате. Старые материалы `docs/superpowers/`
  и `docs/plans/` сохраняют контекст решений, а не управляют текущей работой.
- Старые даты, результаты и пустые чекбоксы не переписывай как текущие факты.
  При продолжении задачи сначала сверь план с кодом и git.
- Документация и интерфейс по-русски; тела PR и комментарии кода по-английски.
  Конкретные действия, без филлеров, em-dash и эмодзи; используй `stop-slop`,
  если он доступен. Отсутствие skill не блокирует правку.
- Проверяй пути, относительные ссылки и команды. Секреты, дампы и содержимое
  `.env` в документацию не включай. Личные файлы ревью не правь вне задачи.
